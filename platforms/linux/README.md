# Linux local development

Run `bash platforms/linux/dev-container.sh [TARGET] [CONTAINER_NAME]` from the host to create or start a retained development container. `TARGET` defaults to `linux-arm64` and can also be `linux-x86_64`; the container uses `linux/arm64` or `linux/amd64` respectively. The default names are `pg-binaries-linux-arm64-dev` and `pg-binaries-linux-x86_64-dev`. Each container mounts the repository at `/repo` read-only and its persistent work directory at `/work`. Agents can enter the ARM64 container with `docker exec -it pg-binaries-linux-arm64-dev bash` and install further tools there as needed. The helper leaves running containers untouched and never stops them.

`build-postgresql-local.sh OUTPUT_DIR` builds PostgreSQL and copies its runtime archive, development archive, checksums and output manifest to the host. `build-extension-local.sh PACKAGE DEVELOPMENT_ARCHIVE OUTPUT_DIRECTORY [TARGET] [CONTAINER_NAME]` builds one extension package against a private copy of the supplied development archive and copies its archive, checksum and output manifest to the host. The optional target defaults to `linux-arm64`; the container name defaults to that target's standard name. Existing three argument calls continue to use ARM64.

Extension workspaces and outputs persist under `/work/local-iteration/<TARGET>/<PACKAGE>`, separated by package and target. The helper reuses the workspace through `--reuse-workspace`; a concurrent build of the same workspace fails on its lock. It caches each PostgreSQL development archive under its SHA-256 and keeps source downloads, Rust tools and Cargo state under `/work`. Separate container names give agents independent writable environments while sharing the read-only repository mount.

Stopping a named container retains its installed tools and files; removing it removes the container, while its host-mounted work directory remains. New containers default to `out/local-environments/<container-name>/` for this work directory. `PG_BINARIES_LINUX_WORK` selects another location at creation; existing container mounts are retained.

The separate `verification/linux/run-local.sh [--target TARGET] POSTGRESQL_ARCHIVE OUTPUT_DIRECTORY [PACKAGE=ARCHIVE ...]` command checks final archives in a clean, disposable container. The target defaults to `linux-arm64`; `linux-x86_64` uses the amd64 verifier. Verification keeps its installation, database and Unix sockets on writable storage inside the container, then copies completed reports to the host. Host-mounted socket directories fail PostgreSQL's permission changes on the current Docker setup.
