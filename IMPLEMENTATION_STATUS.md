# Spike 2 implementation status

The active implementation goal covers milestones 2–7 in `SPIKE2_MILESTONES.md`. The current design remains the authority for build behaviour. Publication requires separate human authorisation.

## Current slice: local macOS ARM64 build

- `HUMAN_REVIEW_QUEUE.md` now asks whether the first PostGIS package must include raster and SFCGAL despite their larger dependency closure. The current full selection remains in force; PostGIS recipe work is paused pending that decision. Other packages and PostgreSQL can proceed.
- `support.json` selects PostgreSQL 18.6, nine extension packages containing the ten selected projects, and macOS ARM64 with a provisional minimum macOS version of 11.0. The SHA-256 values for PostgreSQL and all ten project source archives match downloaded bytes. PostgreSQL's six source-built dependencies are pinned there. Extension build inputs still need completion.
- `LICENSES.md` records the selected projects and PostgreSQL's six source-built dependencies. It still needs review against the libraries and data actually packaged by the extension recipes.
- `build.py` dispatches PostgreSQL dependency, build and package commands, extension builds, build records, archive checks, runtime checks and the release check. PostgreSQL has source build, dependency build and runtime/development packaging recipes. The development archive carries PostgreSQL and its dependency prefix for extension jobs; its checksum is recorded and checked during run selection. A synthetic packaging run confirmed that both development trees are present and the runtime archive excludes build dependencies. The shared macOS bundler stages non-system libraries and rewrites their load paths. No PostgreSQL compilation has run in a local VM.
- The build-record writer hashes supplied archive bytes and records selected sources, build inputs and the PostgreSQL archive declared for an extension build. The release checker requires all selected archives and build records, rejects mismatched hashes, source selections, build inputs or PostgreSQL ancestry, and tests each package alone, PostgreSQL alone and the complete combination. It writes a JSON report with named check outcomes and continues after combination failures. `build.py select-runs` examines only supplied workflow runs, selects each component from the last run with its named artefact, checks archive hashes, selected inputs, build revisions and PostgreSQL ancestry, and can invoke the release check. Synthetic tests cover record selection, stale inputs, originating runs, replacement selection, failed checks and unsafe archives.
- The draft `.github/workflows/spike2-macos-arm64.yml` schedules a PostgreSQL build, independent package jobs and a fresh verification job on standard hosted runners. [Run 40586176637](https://github.com/BernieSumption/pg_binaries/actions/runs/40586176637) compiled and installed PostgreSQL 18.6 and its selected dependencies, then failed because the bundler did not resolve bare ICU library names. [Run 40588015083](https://github.com/BernieSumption/pg_binaries/actions/runs/40588015083) succeeded after that fix. Its runtime and development archives match their build record; the archive checker accepts the runtime bytes. A local static check found no findings in 128 Mach-O files, and the archive contains 46 built-in SQL extension controls. The successful build took 874 seconds and sampled a peak of 0.92 GB above initial filesystem use.
- A branch-push trial now selects the eight extension packages with recipes and the PostgreSQL artefact from run 40588015083. It omits PostGIS only while its queued scope decision remains open. The trial also starts PostgreSQL-only runtime verification in a fresh runner. The workflow's manual full-build, one-package retry and complete verification paths remain available after the workflow reaches the default branch. The full workflow cannot succeed until PostGIS has a recipe.
- [Run 40590558341](https://github.com/BernieSumption/pg_binaries/actions/runs/40590558341) built pgvector, HypoPG, collection, pg_ivm, pgAudit and pgTAP packages. Address Standardizer failed because its version macro reached the compiler as a number rather than a string; pg_jsonschema failed because its development `initdb` had no library search path to the sibling dependency prefix. PostgreSQL-only verification passed archive, native-library, startup, SQL, diagnostic and TLS checks. Its capability and built-in probes could not start their separate servers because their Unix socket paths exceeded the macOS limit. Focused fixes for all three failures are ready for another runner trial. The next branch trial also checks each extension archive in a fresh runner.
- Build jobs record elapsed time and sampled peak filesystem use, including failed builds. The disk figure measures the runner volume and can miss short peaks between samples; it is not an exact count of job-owned bytes. The measurement wrapper and its failure path have synthetic tests.
- `build.py inventory-draft` can write an unpublished inventory from passing verification reports for every declared target. It maps package downloads and selected SQL extensions, including the separately released TIGER Geocoder, and records built-in extensions only on targets where they were verified. The command rejects missing combinations, targets and archives. Synthetic tests pass; no compiled archives or public download URLs have been verified for this draft.
- `build.py publication-preflight` checks an unpublished inventory against selected local archive bytes, `support.json` and passing verification reports for every target. It checks archive hashes, safe archive structure, SQL control files, inventory metadata, a shared release tag, package mappings and download URL filenames. Seven synthetic tests pass. Public accessibility and licence coverage still require checks against a candidate release.
- New package-local macOS ARM64 recipes and SQL probes have been added for pgvector, HypoPG, collection, pg_ivm, pgAudit, pgTAP, Address Standardizer and pg_jsonschema. Their shell syntax checks pass, but none has yet built against a Spike 2 PostgreSQL archive. Their probes assume the runtime checker has applied inventory configuration and created the advertised SQL extensions. The runtime checker also inspects server logs for pgAudit records.
- The archive checker validates final tarball bytes, path and link safety, and overlapping files before extraction. Its four focused tests pass. The runtime checker records named results for archive safety, contents, extraction, native libraries, configuration, database startup, SQL probes and diagnostics. A required check that cannot run fails the release result; a check that applies only to PostgreSQL alone is marked inapplicable elsewhere. Unsafe archives stop before extraction, while independent PostgreSQL probes continue after a database startup failure. The checker removes the extracted installation and main database after each combination, retaining logs. A remaining `postmaster.pid` stops cleanup and fails the result.
- PostgreSQL-specific probes sit with the PostgreSQL recipes and remove their database directories after a confirmed stop. They exercise ICU, XML/XSLT, PL/pgSQL, LZ4 and compressed dumps, derive the 46 expected built-in controls from source, create each built-in SQL extension and run representative operations, including TLS and sslinfo. After the PostgreSQL-only checks pass, the verification report records the built-in control names found in the PostgreSQL archive for inventory generation. Diagnostic checks provoke a SQL error and a missing-library error. None of these runtime probes has yet run on a compiled archive.
- PostGIS 3.6.4 has `--without-address-standardizer` and `--without-tiger` configure switches. Its separate runtime-library closure and potential overlaps with PostgreSQL motivated the queued scope review before a long port.
- Lume 0.6.1 created the disposable VM `spike2-macos-arm64`, but unattended setup could not make SSH available. Its separate offline setup completed the disk patch and then failed 60 SSH health checks. The VM is stopped and preserved; no build ran in it. The human review queue asks whether to trial a Tart base image or select another environment. Lume use is paused.
- Docker is available for local Linux ARM64 work. The Linux design currently names only a kernel minimum; Spike 1's libc-bundling and launcher machinery would be substantial to carry forward. The human review queue asks whether to use a distribution userspace baseline instead. Linux archive implementation is paused pending that decision.
