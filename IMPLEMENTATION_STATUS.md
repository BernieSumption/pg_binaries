# Spike 2 implementation status

The active implementation goal covers milestones 2–7 in `SPIKE2_MILESTONES.md`. The current design remains the authority for build behaviour. Publication requires separate human authorisation.

- `HUMAN_REVIEW_QUEUE.md` now asks whether the first PostGIS package must include raster and SFCGAL despite their larger dependency closure. The current full selection remains in force; PostGIS recipe work is paused pending that decision. Other packages and PostgreSQL can proceed.

The SHA-256 values for PostgreSQL and all ten project source archives match downloaded bytes. PostgreSQL's six source-built dependencies are pinned for both Mac targets. Extension build inputs still need completion.

- `build.py` dispatches PostgreSQL dependency, build and package commands, extension builds, build records, archive checks, runtime checks and the release check. PostgreSQL has source build, dependency build and runtime/development packaging recipes. The development archive carries PostgreSQL and its dependency prefix for extension jobs; its checksum is recorded and checked during run selection. A synthetic packaging run confirmed that both development trees are present and the runtime archive excludes build dependencies. The shared macOS bundler stages non-system libraries and rewrites their load paths. No PostgreSQL compilation has run in a local VM.
- The build-record writer hashes supplied archive bytes and records selected sources, build inputs and the PostgreSQL archive declared for an extension build. The release checker requires all selected archives and build records, rejects mismatched hashes, source selections, build inputs or PostgreSQL ancestry, and tests each package alone, PostgreSQL alone and the complete combination. It writes a JSON report with named check outcomes and continues after combination failures. `build.py select-runs` examines only supplied workflow runs, selects each component from the last run with its named artefact, checks archive hashes, selected inputs, build revisions and PostgreSQL ancestry, and can invoke the release check. Synthetic tests cover record selection, stale inputs, originating runs, replacement selection, failed checks and unsafe archives.
