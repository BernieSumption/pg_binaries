# Verification of packaged downloads

Clients use downloaded archives to create and inspect PostgreSQL schemas. Verification must run against final archive bytes, using the installation procedure in [install-process.md](install-process.md), because a successful build does not establish that a client can use the package.

## Evidence and eligibility

Each verification record must identify archive SHA-256, source and component versions, test revision, operating system and architecture, environment image or runner version, test cases, and outcome. A failure, skip, missing record, or record for different bytes or tests must not satisfy a claim. A build and its verification may be reused only when their inputs and claimed compatibility remain applicable. The coverage report described in [delivery-process.md](delivery-process.md) must distinguish missing intended coverage from broken published downloads.

The Linux PostgreSQL pilot archive includes `LICENSES/inventory.json`. Its component entries identify the PostgreSQL or runtime package version, the PostgreSQL payload directories or exact copied runtime library paths, the included license text, and a source URL. The bundled glibc and static launcher entries also identify exact source-package versions and source archives; the glibc entry lists referenced licence texts. The archive carries standard licence texts referenced by package copyright files. The archive verifier checks that mapped files and licence texts exist in the extracted archive and that every copied runtime library and launcher binary has exactly one package mapping. This checks archive provenance and mapping completeness; it does not determine whether a licence permits redistribution.
The PostGIS Linux pilot also includes `LICENSES/inventory.json`. It maps the selected SQL modules, extension scripts, each copied runtime library, and the PROJ and GDAL data directories to the PostGIS or Ubuntu package version, included licence text, and exact-version source link. The PostGIS entry records the downloaded source archive's SHA-256. The archive includes the standard licence texts referenced by package copyright files. Its verifier checks these mappings and referenced texts against the extracted payload; a source URL is evidence of where to obtain source, not a legal conclusion about redistribution. Successful CI checks emit one `pilot-smoke` record for each of the four tested SQL extensions, bound to both the PostGIS and assembled PostgreSQL archive checksums, the PostGIS test profile, and clean verification environments. These records do not qualify the archive for publication.

Records must distinguish pilot smoke checks from publication checks. A passing publication record must name a full test commit, unique case identifiers, the verification image, and the runtime dependency-check profile and result. Pilot records remain useful for development but must not satisfy publication coverage. The profile registry binds each record to a named case set and the current bytes of its test sources; a changed suite makes old records stale without discarding them. Only pilot profiles are registered so far. A forged `publication` label on pilot evidence cannot satisfy coverage or candidate checks, and no current profile establishes release eligibility.

Before an archive is eligible for publication, a verifier outside its build environment must assemble the installation from archives and metadata alone. The verification environment must not supply development files or unbundled runtime libraries that conceal missing dependencies. A fresh job on a developer-equipped image, by itself, does not establish this property. Record the exact operating system and runtime dependency checks used to establish it.

For each supported OS and architecture, verify the minimum supported OS and a current supported OS. For an extension archive claiming a PostgreSQL range, verify both range endpoints. A known incompatible intermediate version splits the range even if its endpoints pass. A new PostgreSQL release, OS baseline, dependency, or test revision must invalidate only the evidence it affects; unchanged applicable results may be reused.

## PostgreSQL and extension behaviour

From the extracted archive, run `initdb` as an ordinary user with UTF-8 encoding, start `postgres` with `pg_ctl`, connect through packaged `psql`, apply representative types, collations, defaults, constraints, indexes, views, functions and procedures, inspect the resulting definitions through catalogues, and stop cleanly. Exercise `pg_dump` and restore the dump with `pg_restore` into a new database, then verify restored definitions. Assert expected results rather than relying on a zero exit status or printed output alone.

Discover included built-in SQL extensions from the final PostgreSQL archive and verify the inventory claim against that discovery. Exercise representative schema behaviour for each advertised built-in extension and enabled option. For each external SQL extension, create the extension, use at least one of its objects in DDL, execute a representative operation, and check its result. These checks detect packaging and compatibility failures; they do not replace upstream's full test suite. Verify version, prerequisite and platform claims against archive metadata, documented upstream compatibility, and endpoint results.

Assemble PostgreSQL and extensions with the documented copy procedure, run representative operations, move the assembled installation, make the old path unavailable, and repeat the operations. Check required data files and library loading after relocation. An agent review of the test installer must confirm that it follows [install-process.md](install-process.md) without undeclared setup.
The PostGIS Linux pilot checks the assembled archive's ELF dependency closure after copying the selected SQL modules and their runtime libraries into the relocated PostgreSQL prefix. This check must resolve every dynamic dependency inside the assembled prefix before the SQL probe, so libraries installed in the clean verifier image cannot mask a missing archive file.
The same pilot runs the four selected PostGIS SQL extensions after relocation in clean Ubuntu 20.04 and Alpine 3.22 containers. These checks exercise the module and data-file closure with an older or absent host glibc, using the bundled core runtime. They share the runner kernel and therefore do not establish Linux 5.15 compatibility.

## Diagnostics and published bytes

Follow [debugging.md](debugging.md) to collect a representative server log error and a system-level loader or crash failure. Verify that retained evidence lets a maintainer identify the archive and investigate the failure, including symbol resolution where applicable.

After a release, retrieve `inventory.json` anonymously from the public latest-release URL. Download every referenced archive, including those on older releases, verify its checksum, and compare its bytes with the archive that passed pre-publication tests. A local candidate inventory cannot substitute for this published-download check.

## Cost and current coverage

Routine checks must use metadata-derived combinations and reuse valid evidence so they can run within standard GitHub-hosted runner limits. If complete required coverage would imply thousands of combinations, put a proposed resolution in `HUMAN_REVIEW_QUEUE.md` before changing the test requirement.

The Linux pilots accept one declared PostgreSQL 15 through 18 minor at a time, selecting the highest missing declared core target for each architecture when no version is supplied. The current support snapshot selects 18.6, paired with pgvector 0.8.7. Native Ubuntu 24.04 runners on x86-64 and arm64 check built-in SQL extensions, enabled options, dependency loading, dump and restore, and relocation. Clean Ubuntu 20.04 and Alpine 3.22 containers then check operation with an older or absent host glibc. Containers share the runner kernel, so they do not test the Linux 5.15 floor. PostgreSQL 15 uses numeric `pg_dump` compression; PostgreSQL 16 through 18 use zstd.

The combined [x86-64](https://github.com/BernieSumption/pg_binaries/actions/runs/38975180522) and [arm64](https://github.com/BernieSumption/pg_binaries/actions/runs/38975180567) jobs passed the full archive verifier in fresh Ubuntu 22.04 Linux 5.15 QEMU guests on the same archive bytes tested by their current-OS runners. Separate minimum-kernel records and guest output are retained under `support/verification/` and `support/evidence/`. The macOS x86-64 and arm64 pilots build and verify PostgreSQL 18.6 and pgvector 0.8.7 on native `macos-15-intel` and `macos-15` runners. Their current-OS checks do not test the macOS 11 minimum. These pilot results do not establish the full intended product matrix in `support.json`.

The x86-64 pilot archives built on 2026-10-16 contain 47 built-in controls in PostgreSQL 15.19 and 16.15, 45 in 17.11, and 46 in 18.6. Version-specific cases cover `adminpack` and `old_snapshot` in 15 and 16, and `pg_logicalinspect` in 18. The verifier fails if an available extension remains uninstalled after its behaviour checks. `pg_surgery` performs its unsafe operation only in a separate disposable database after dump and restore. TLS certificates are generated inside the verifier container to check `sslinfo` through the packaged client. The [first arm64 build and archive verification](https://github.com/BernieSumption/pg_binaries/actions/runs/38954674617) passed on 2026-10-16.

Successful Linux pilot jobs emit `pilot-smoke` verification records for the PostgreSQL and pgvector archive checksums. Each record binds the current test profile, CI commit and run, verifier image, runner kernel, and dependency-check result. The [x86-64](https://github.com/BernieSumption/pg_binaries/actions/runs/38968717817) and [arm64](https://github.com/BernieSumption/pg_binaries/actions/runs/38968717801) static-launcher runs passed on 2026-10-16, including the no-host-user-space launch and older or absent host glibc checks. Their four checksum-bound JSON records are retained under `support/verification/` so the coverage checker can read them after the three-day Actions artifacts expire. The Linux 5.15 QEMU smoke tests also passed on [x86-64](https://github.com/BernieSumption/pg_binaries/actions/runs/38968717766) and [arm64](https://github.com/BernieSumption/pg_binaries/actions/runs/38969842579); their guest output and archive checksums are retained under `support/evidence/`. These results remain pilot evidence; neither a publication profile nor the required product-matrix tests exists yet.

The Linux x86-64 pilots for PostgreSQL [15.19](https://github.com/BernieSumption/pg_binaries/actions/runs/38954284096), [16.15](https://github.com/BernieSumption/pg_binaries/actions/runs/38954284089), [17.11](https://github.com/BernieSumption/pg_binaries/actions/runs/38952584371) and [18.0](https://github.com/BernieSumption/pg_binaries/actions/runs/38951633511) passed on Ubuntu 24.04 on 2026-10-16.
