# First-release metadata corrections

On 2026-10-22, 28 previously verified extension archives were repacked to add a missing `postgresql_version` field or explicit empty prerequisite arrays to root `metadata.json`. [The manifest](manifest.json) maps each original and corrected SHA-256 to its member proof and derived verification records. Each proof records the metadata change and the unchanged members. The one-off code in `experiments/metadata_repack/` reopened both archives and compared member paths, contents, types, modes, ownership, timestamps and link targets. The corrected archives also passed current static metadata and licence-pointer checks.

The added pgvector macOS arm64 archives target PostgreSQL 15.19 and 16.15, and the macOS x86_64 archive targets PostgreSQL 16.15. Four added Windows PostGIS archives target PostgreSQL 15.19, 16.15, 17.11 and 18.6; each has four derived SQL-name records. The original records remain in `support/verification/`. Each derived record names its original record hash and proof, retains the original runtime case outcomes, and identifies the corrected archive checksum. The original archives are retained locally under ignored `dist/first-release/original-metadata-archives/`; corrected copies are staged under ignored `dist/first-release/archives/`. No runtime payload member changed.

The PostgreSQL 18.6 macOS arm64 `pg_jsonschema` archive had the same metadata omission, but its runtime profile is stale after a verifier edit. It has no derived passing record here; [run 39705481248](https://github.com/BernieSumption/pg_binaries/actions/runs/39705481248) was dispatched for fresh final-archive verification.
