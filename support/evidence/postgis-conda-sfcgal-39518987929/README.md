# macOS arm64 PostGIS four-name source-build feasibility

On 2026-10-21, [run 39518987929](https://github.com/BernieSumption/pg_binaries/actions/runs/39518987929) built unmodified SFCGAL 2.3.0 from tagged commit `137203dae01faab4a1287934f9457e925e3b4383` against conda-forge CGAL 6.1.1, then built unmodified PostGIS 3.6.4 against the selected PostgreSQL 18.6 arm64 core. The [SFCGAL](sfcgal-configure.log) and [PostGIS configure outputs](configure.log) record the selected toolchains and dependency versions, including GDAL 3.13.3, GEOS 3.14.1, PROJ 9.9.0 and SFCGAL 2.3.0. The [selected core target](target.json) identifies the exact core archive used.

The [SQL probe](sql-probe.txt) created `postgis`, `postgis_raster`, `postgis_sfcgal` and `postgis_topology`, then exercised coordinate transformation, raster creation, topology creation and the SFCGAL version function. The [installed SQL-name list](sql-names.txt) confirms all four control files. This proves source-build and local SQL feasibility on the runner. It does not establish a relocatable archive, macOS dependency closure, bundled PROJ/GDAL data, resolved redistribution review or a final-archive publication record. The trial uses temporary conda-prefix load paths; a publication recipe must replace them with paths inside the assembled download and verify the moved installation.
