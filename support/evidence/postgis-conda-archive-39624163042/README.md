# macOS arm64 PostGIS archive trial

[Run 39624163042](https://github.com/BernieSumption/pg_binaries/actions/runs/39624163042) built unmodified PostGIS 3.6.4 and its SFCGAL dependency against the selected PostgreSQL 18.6 macOS arm64 core. It assembled a separate extension archive with the copied runtime libraries and data. The core archive SHA-256 was `72722e604e7061b188b0683aba7c02d51f75b459c934ffcff51cba6723039123`; the extension archive SHA-256 was `22cb73f3b215bfb7cb9dbea57d32bfb1f9f6ccbef4138db78404927f89e20ec2`.

The separate macOS 15 arm64 verification job relocated both exact archives, inspected 168 Mach-O files against the macOS 11.0 target with no findings, and passed SQL probes for `postgis`, `postgis_raster`, `postgis_sfcgal` and `postgis_topology`. The probes exercised GEOS, PROJ, SFCGAL, topology and raster operations, checked GTiff, PNG and JPEG serialization, and found the protobuf-enabled `ST_AsMVT` and `ST_AsGeobuf` functions. The retained [static report](static-analysis.json) binds the inspected archives to the checksums above; the [PostGIS probe](probe-output.txt) and [raster probe](raster-probe.txt) are outputs from the same verification job.

The [owner report](conda-package-owners.json) traces 39 bundled libraries: 34 to conda packages, three to the checked core and one to the source-built GDAL. It marks `libSFCGAL.2.3.0.dylib` unresolved because the trial's owner matcher looked only for conda package records under that prefix. The [SFCGAL source record](sfcgal-source.json) and build step identify that library as source-built by this recipe; the matcher has since been corrected. The [GDAL source record](gdal-source.json) and [SQL-name list](sql-names.txt) are retained with the owner report. This is diagnostic evidence; the selected publication route still needs its own archive-bound record.
