The verifier assembled and relocated the installation, checked the hypothetical-index SQL probe and inspected 142 PE files. Both publication cases passed. The first [split-workflow run](https://github.com/BernieSumption/pg_binaries/actions/runs/39136998214) passed the archive checks but failed the evidence-import handoff; this run includes the correction.

The [attempt](x86_64/attempt.json), [receipt](x86_64/current-receipt.json) and [record](../../verification/hypopg-1.4.3-postgresql-17.11-windows-x86_64-current-39137163791.json) bind the checks to PostgreSQL archive SHA-256 `c94d4cef57880ec80a4177570ab7c1f2e955f1e799a2d41fb38412e07c435285` and HypoPG archive SHA-256 `a3bc4eda4f9e91a71edd00847d470e33307d6a62ed4773dbc946093c90468109`. These match downloaded archive bytes. The [PE report](x86_64/pe-dependency-analysis.json), [static report](x86_64/static-analysis.json) and [SQL output](x86_64/probe-output.txt) were imported from the verification job. Its image was `win22/20261012.333.1` with Windows version `10.0.20348`; source and test revision `d4434e10138243089bc04e3a3a940063e6cc3ead`.

This verifies the separate-runner structure for one Windows extension target. Other Windows extension workflows require their own split before their records meet the same environment rule. The archives remain unpublished.
