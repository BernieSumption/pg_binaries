# Selected Windows core dependency redistribution review

On 2026-10-20, the selected PostgreSQL 18.6 Windows x86-64 archive from [run 39444631332](https://github.com/BernieSumption/pg_binaries/actions/runs/39444631332) matched SHA-256 `7dee5b25cde652310715b8e46d7af66279e0d532c7996e6db674efd090a21b83`. The retained [DLL map](vcpkg-dll-map.json) and [component inventory](core-license-inventory.json) were extracted from those exact archive bytes. The map attributes 16 bundled DLLs to eight versioned vcpkg ports; the inventory still marks their combined redistribution review pending. Other PostgreSQL majors require their own final-archive checks before publication.

The pinned [vcpkg libiconv 1.19 port](https://github.com/microsoft/vcpkg/blob/9e593bb18ea69cc5095e012465dcd675a822ed0d/ports/libiconv/portfile.cmake) builds GNU libiconv on Windows from a checksum-pinned source archive and applies three distribution patches. Its packaged notice, `LICENSES/dependencies/libiconv.txt`, states that `iconv-2.dll` and `charset-1.dll` are LGPL libraries. The included LGPL-2.1 text requires corresponding source for redistributed library object code, or equivalent source access from the same distribution place. The current core archive contains the licence text but no corresponding libiconv source or patches. This is a concrete publication blocker for these two DLLs, independent of their successful runtime tests. The port's GPL notice covers its separately licensed iconv program and documentation; neither program nor documentation is among the mapped DLL payloads.

The mapped `zstd.dll` is zstd 1.5.7. The [pinned vcpkg port](https://github.com/microsoft/vcpkg/blob/9e593bb18ea69cc5095e012465dcd675a822ed0d/ports/zstd/portfile.cmake) builds the shared library with upstream CMake defaults and packages the top-level BSD/GPL texts. [Upstream CMake](https://github.com/facebook/zstd/blob/v1.5.7/build/cmake/lib/CMakeLists.txt) enables the dictionary builder by default and includes every `lib/dictBuilder/*.c` file in that library. The included [`divsufsort.c`](https://github.com/facebook/zstd/blob/v1.5.7/lib/dictBuilder/divsufsort.c) carries a separate Yuta Mori copyright and permission notice. Direct inspection of this exact core archive found only the top-level BSD/GPL texts in `LICENSES/dependencies/zstd.txt`; it did not find the divsufsort notice. Supply the exact upstream notice with the archive and map it to `zstd.dll` before resolving that component. This is an additional concrete redistribution gap, not a claim that zstd requires source delivery.

A candidate source-delivery route is to publish a separate source asset beside the binary archive, containing the exact GNU source archive, the three applied vcpkg patches and its portfile. Verify their identities and availability before marking libiconv resolved. This avoids adding development-only source to every PostgreSQL download. The current release policy and tooling do not yet stage such a companion asset, so this remains implementation work. Review the other seven ports against their exact packaged notices and source identities, then replace the aggregate pending component with version-keyed DLL components. No public download or redistribution decision is claimed by this note.
