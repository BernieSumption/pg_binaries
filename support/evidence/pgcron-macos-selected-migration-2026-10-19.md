# pg_cron macOS selected-path trial, 2026-10-19

The PostgreSQL 18.6 and pg_cron 1.6.8 selected path now accepts either Mac architecture through the shared dispatcher. It resolves a checked PostgreSQL archive, builds one pg_cron archive, and verifies the final bytes on a fresh runner after relocating the assembled installation. The verifier checks the Mach-O dependency closure, static archive reports, extension creation, and a scheduled background-worker SQL job.

The first arm64 attempt, [run 39194830328](https://github.com/BernieSumption/pg_binaries/actions/runs/39194830328), built the extension but failed because the new verifier expected an upstream `pg_cron--1.6.sql` file that pg_cron does not ship. Upstream supplies `pg_cron--1.0.sql` and an upgrade script through 1.6. The failed attempt and receipt were imported from the CI artifact and retained under `support/evidence/pgcron-macos-publication-39194830328/arm64/`.

[Arm64 run 39195367346](https://github.com/BernieSumption/pg_binaries/actions/runs/39195367346) and [Intel run 39195608216](https://github.com/BernieSumption/pg_binaries/actions/runs/39195608216) passed at revision `492c29e3f2e9253cfa240a52a5e581612812de22`. Both used checked PostgreSQL core candidates and passed fresh-runner verification. Their publication artifacts were independently imported using the exact source revision; the five retained files and verification record for each run matched the corresponding CI files byte-for-byte. The records bind the final pg_cron archive SHA-256 to the resolved core SHA-256 and profile revision.

The passing arm64 run used 8 seconds for planning, 5 for selection, 36 for building and 57 for verification. The Intel run used 7, 5, 33 and 134 seconds respectively; most of the Intel verification time was the scheduled-job probe. These are observed job durations, excluding queue delay. The later removal of the emitter's pinned-core fallback changes both profile revisions, so the results above are historical and the final selected path needs a refresh.
