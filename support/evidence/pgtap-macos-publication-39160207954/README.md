# Selected-target pgTAP macOS arm64 trial

[GitHub Actions run 39160207954](https://github.com/BernieSumption/pg_binaries/actions/runs/39160207954) built pgTAP 1.3.4 for PostgreSQL 17.11 on a macOS 15 arm64 runner, then verified the final archives on a fresh runner. The build used commit `a8417c3dd0bf94e4aff5bc9d000931343ba09147`. Both `archive-suite` and `static-analysis` passed; the relocated SQL probe returned four successful assertions.

The build and publication artifacts were downloaded separately and imported with `tools/import_pgtap_macos_publication.py`. The importer checked the core archive SHA-256 `d9ac809946cd87bbb585135d0ff329d33d5563047b9caaa312aea9116a8d9eaa` and pgTAP archive SHA-256 `144b013c353710e3782c3e6d42c06328cffd7ec324a7ff24b9e427f9217b55fa` against the target pin, attempt, receipt and static report. The [verification record](../../verification/pgtap-1.3.4-postgresql-17.11-macos-arm64-current-39160207954.json) matches the current profile revision `01a8028e993a9ddfe354282fae730c4fb8ca0ebbe071befcf69b7359084af13f`.

An independent review of `scripts/pgtap/verify-macos-publication.sh` found that extraction, merge collision checks, relocation, static inspection and the runtime probe follow `policies/install-process.md` and `policies/testing.md`. The workflow requires both cases to pass. This result covers the selected PostgreSQL and pgTAP archives on the named runner image; it does not establish the remaining PostgreSQL versions or public-release availability. The three jobs used about 60 runner-seconds in total, with a 53.2 MB temporary build artifact and a 257 KB publication artifact.
