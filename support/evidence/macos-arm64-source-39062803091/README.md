# Apple Silicon source-built archive pilot

[Run 39062803091](https://github.com/BernieSumption/pg_binaries/actions/runs/39062803091) at revision `75f27f6a0cad0c6ad515d4db55dba0f6cd85304a` built PostgreSQL 18.6, pgvector 0.8.7 and their macOS dependencies from pinned upstream sources for arm64. A separate `macos-15` runner passed relocation, archive behaviour, built-in and pgvector SQL, symbol verification and [static analysis](static-analysis.json). The report inspected 133 Mach-O files, found no dependency or minimum-target violations, and recorded macOS 11.0 as every inspected file's deployment target.

The PostgreSQL archive SHA-256 is `2ef5d2060a1d8229956b316db92563c16e868e66acac5d0be43103177a0adc03`; the pgvector archive SHA-256 is `54465295c614a6fc17f3e6378c84a3a2277f4ce0717d9e63ab3b3eb94d486704`. Both downloaded archive hashes match the static report and the [PostgreSQL](../../verification/postgresql-18.6-macos-arm64-39062803091.json) and [pgvector](../../verification/vector-18.6-macos-arm64-39062803091.json) passing records. Both records validated against the test suite and support metadata at their producing revision.

The independent `check_macos_license_inventory.py` check on these downloaded archives mapped 136 native PostgreSQL payload paths across seven declared components and the pgvector module to nonempty licence texts. The exact [PostgreSQL licence inventory](license-inventory.json) is retained. This run predates the check's integration into routine verification. Component redistribution reviews remain pending, so this pilot is not publication clearance.
