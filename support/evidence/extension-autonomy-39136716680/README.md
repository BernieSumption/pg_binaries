# Bounded extension onboarding trial, 18 October 2026

The [passing GitHub Actions run](https://github.com/BernieSumption/pg_binaries/actions/runs/39136716680) built unmodified upstream pg_partman 5.5.0, pg_repack 1.5.3 and pg_squeeze 1.9.4 for PostgreSQL 18.6 on Linux x86-64. Each job assembled the final archives in a separate Alpine container, started the relocated PostgreSQL installation, ran the extension SQL probe and passed ELF dependency inspection. These are feasibility archives, not declared support or publication records. The temporary Actions artifacts expire on 25 October 2026.

- `pg_repack`: archive SHA-256 `df1b1faf7cd5677cd1c3a386f3fb432a64d4b23c9ba4b7b8f05ab410daf8d49f`, 270,149 bytes; ELF inspection passed for 187 files; runner job 52 seconds.
- `pg_squeeze`: archive SHA-256 `2efe3fac93a11e0a9a21216272d9d98846869e0b7784eee3bc24e96b07c49929`, 259,080 bytes; ELF inspection passed for 185 files; runner job 52 seconds.

Two independent Luna agents drafted pg_repack and pg_partman; both initially misread the project's major-version timing rule. A reviewer corrected their research and added the [extension feasibility guide](../../adding-an-extension.md). A third Luna agent used that guide to draft pg_squeeze and applied the rule correctly. The first [CI run](https://github.com/BernieSumption/pg_binaries/actions/runs/39136361510) failed on both initial PGXN source URLs. The [second run](https://github.com/BernieSumption/pg_binaries/actions/runs/39136529533) passed pg_partman, then exposed missing PostgreSQL link dependencies in the pg_repack build container and a PostgreSQL 18 output-plugin setting needed by pg_squeeze. Root reviewed and corrected these issues before the passing run. Total trial execution used two jobs in the first run and three jobs in each later run, all on standard GitHub-hosted Linux runners. Manual supervision included task scoping, version research review, CI diagnosis and repair, and evidence inspection.

The passing run establishes the behavior exercised for these three exact archive hashes on that runner and verifier image. It does not establish complete release support, redistribution approval or applicability to other targets. The downloadable archives were inspected after the run, and their SHA-256 values above match the downloaded bytes. Full workflow logs and temporary artifacts remain linked from the run while retained by GitHub.
