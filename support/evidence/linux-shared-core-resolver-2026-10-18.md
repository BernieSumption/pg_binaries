# Shared Linux core resolver trial

The selected PostgreSQL 17.11 Linux x86-64 paths now use one core resolver. On 2026-10-18, [pgvector run 39176039882](https://github.com/BernieSumption/pg_binaries/actions/runs/39176039882) and [HypoPG run 39176039827](https://github.com/BernieSumption/pg_binaries/actions/runs/39176039827) passed from revision `f57b527e9cc2437e65afa9c09dc60047cd4f0cce`. Both ran final-archive verification. The pgvector run passed its relocated Alpine archive suite, diagnostics and no-host-userspace case; the HypoPG run passed its relocated archive suite. Their independently imported records bind the exact core and extension archive hashes.

- [pgvector evidence](linux-publication-39176039882/postgresql-17.11/x86_64/current-receipt.json) binds core SHA-256 `29c87410cf53c4a0b56fd86298210c84f234c199b55bdc750b8d17f34cf1d39e` and pgvector SHA-256 `c156e765d1802cd6a4087103625a3223fe34ff105658f04815ff05ced9f3c3d3`.
- [HypoPG evidence](hypopg-publication-39176039827/x86_64/current-receipt.json) binds core SHA-256 `ad56c70f07cb8ae12f149a87d2bd6e6bb58dbb90a76cde150bf23775b537340b` and HypoPG SHA-256 `65688d25187abe4ede580a3889ede9684388fdc4b6740b80534aa2d17f18eaf9`.

Both runs rebuilt PostgreSQL after rejecting older candidates. The log showed one new cause: an archive reused and republished by a later run retained its original build revision in the core manifest, while candidate validation compared that revision with the republishing run. The validator now distinguishes the build revision from the artifact run revision and checks core-recipe changes against the build revision. This correction passed focused local tests but requires a later CI run to prove cross-run reuse. The fallback still used the combined PostgreSQL/pgvector builder in these runs; a core-only fallback remains to be verified.
