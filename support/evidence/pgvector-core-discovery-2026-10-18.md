# Checked Linux core discovery for the pgvector trial

The pgvector separate-build trial previously pinned one PostgreSQL 18.6 Linux x86-64 Actions run. It now searches recent successful `linux-publication.yml` runs on `spike` for an unexpired `linux-publication-x86_64-evidence` artifact. Discovery checks the GitHub artifact ZIP digest, the archive checksum sidecar and the exact target filename. Before building, the recipe checks the embedded core manifest's PostgreSQL version, platform, architecture and source archive SHA-256 against the selected release snapshot. The build job passes the discovered source run and core SHA-256 to the fresh-runner job, which downloads that same artifact and checks its bytes again.

[Run 39165646257](https://github.com/BernieSumption/pg_binaries/actions/runs/39165646257) at revision `7a35f4c51f8fdb5e204d8aec5d78a4aa43988d9c` discovered core SHA-256 `67197597ee58b85b88b6a9e541bd5851194233d6c0ed1e34969163528f1cba6f` from [Linux publication run 39162158901](https://github.com/BernieSumption/pg_binaries/actions/runs/39162158901). That differs from the trial's former core pin. The work queue rejected the prior pgvector archive for a build-input identity mismatch, and the job built a new archive. The separately downloaded static-analysis report records `passed` for that core and pgvector archive SHA-256 `aad080c68b3f5fd347c8ebc643f70ee22f1e63c35d2c00879569adfe10522075`; the log ends with successful Alpine v3.22 relocation and SQL checks. The build and verification jobs took 49 and 23 seconds.

The recipe then gained the source SHA-256 check. [Run 39165832857](https://github.com/BernieSumption/pg_binaries/actions/runs/39165832857) at revision `98d42255279e192ca04441b2f85085e62f3ec54b` passed with the same discovered core. Its final pgvector archive SHA-256 is `93fadbaab72d44b991182505ca8fb4b1bddda1ae9e51fa9a25804d212d3f1258`; the downloaded static-analysis report records `passed` for that extension and the core SHA above. The artifact ZIP digests matched the GitHub API claims. Build and verification jobs took 42 and 24 seconds.

[Run 39165956380](https://github.com/BernieSumption/pg_binaries/actions/runs/39165956380) at revision `04a6ddaf425ecad1db57a939d313265027bae124` repeated the one-target trial without a recipe or core-input change. Its build log reports `Candidate reuse: accepted` for pgvector SHA-256 `93fadbaab72d44b991182505ca8fb4b1bddda1ae9e51fa9a25804d212d3f1258` and `Archive action: reused checked prior candidate`. The separate verifier downloaded the same core source run, checked its SHA-256, and reported `passed` for the same core and extension hashes. Build and verification jobs took 44 and 39 seconds. The ZIP digest of the downloaded verification report matched the GitHub API claim.

The trial now has checked discovery and reuse for both inputs, rejection after a core-byte change, and a repeatable single-target workflow. It still names one PostgreSQL and pgvector release, and discovery depends on a temporary core artifact remaining available. It has no automatic core-build fallback, general selected-target dispatch or publication record. The `workflow_dispatch` entry point can be used once this workflow exists on the repository's default branch; it is currently only on `spike`, so these runs used the scoped push trigger.
