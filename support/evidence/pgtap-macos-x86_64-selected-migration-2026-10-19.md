# pgTAP macOS Intel selected-target migration

The selected-target workflow built pgTAP 1.3.4 for each declared PostgreSQL release on macOS Intel, then verified the final PostgreSQL and pgTAP archives on a fresh runner. It preserves the four SQL probe assertions, relocation and Mach-O static analysis from the release-specific workflows. The four predecessor workflows had no distinct build or verification behavior and were removed after the selected path passed all their targets.

- PostgreSQL 15.19: [run 39193079129](https://github.com/BernieSumption/pg_binaries/actions/runs/39193079129), [record](../verification/pgtap-1.3.4-postgresql-15.19-macos-x86_64-current-39193079129.json), 235 runner-seconds.
- PostgreSQL 16.15: [run 39193072544](https://github.com/BernieSumption/pg_binaries/actions/runs/39193072544), [record](../verification/pgtap-1.3.4-postgresql-16.15-macos-x86_64-current-39193072544.json), 131 runner-seconds.
- PostgreSQL 17.11: [run 39193062530](https://github.com/BernieSumption/pg_binaries/actions/runs/39193062530), [record](../verification/pgtap-1.3.4-postgresql-17.11-macos-x86_64-current-39193062530.json), 133 runner-seconds.
- PostgreSQL 18.6: [run 39192759672](https://github.com/BernieSumption/pg_binaries/actions/runs/39192759672), [record](../verification/pgtap-1.3.4-postgresql-18.6-macos-x86_64-current-39192759672.json), 118 runner-seconds.

All four runs used source revision `afb2641e1be50317e052022499ed25500e58a976`. Every record passes the current profile's `archive-suite` and `static-analysis` cases and binds pgTAP to its exact PostgreSQL core. The build and verification artifacts were downloaded and independently re-imported with that source revision; each run's six retained files matched the CI copies byte for byte. The 15.19, 16.15 and 17.11 builds reused checked cores from [pg_jsonschema run 39190688208](https://github.com/BernieSumption/pg_binaries/actions/runs/39190688208); 18.6 reused a checked core from run 39178275001. Candidate manifests retain the source artifact identity and checksum.

The four runs used 617 runner-seconds in total. GitHub accepted direct targeted dispatch of the selected workflow on `spike` for the last three targets. The earlier single-target feasibility workflow was removed after the selected path covered the same assertions and target. The temporary push request remains until planner-driven dispatch replaces it; broader planner candidate selection and other project migrations remain open.
