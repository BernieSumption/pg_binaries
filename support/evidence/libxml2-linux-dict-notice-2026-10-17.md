# Linux libxml2 `dict.c` notice

The Linux core builder bundles Ubuntu Jammy package `libxml2` version and source version `2.9.13+dfsg-1ubuntu0.14`. The upstream v2.9.13 [`dict.c`](https://raw.githubusercontent.com/GNOME/libxml2/v2.9.13/dict.c) has a separate Daniel Veillard permission notice in its file header. The tracked [`libxml2-2.9.13-dict-notice.txt`](../../licences/libxml2-2.9.13-dict-notice.txt) is byte-identical to the start of `dict.c` in Ubuntu's [exact orig source archive](https://archive.ubuntu.com/ubuntu/pool/main/libx/libxml2/libxml2_2.9.13+dfsg.orig.tar.xz), SHA-256 `13cf2e55e603c34143486f4082cbf202859ac1eec5130b8d8e5e3c06a9902d8a`. The only `dict.c` patch in Ubuntu's [exact Debian delta](https://archive.ubuntu.com/ubuntu/pool/main/libx/libxml2/libxml2_2.9.13+dfsg-1ubuntu0.14.debian.tar.xz), SHA-256 `25ff38d4356a491aa49c415cff6460453793694a72e4c9a894b94128e65b8040`, changes function code around line 332 and leaves the header untouched.

The builder stages this notice only for the exact Jammy binary/source package identity. The Linux inventory writer checks its SHA-256 and lists it in `additional_license_files`. This addresses the `dict.c` notice omitted from the packaged copyright file; redistribution reviews for the final archive and the pending upstream-only dependency-source decision remain separate.
