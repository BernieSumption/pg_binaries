The Linux PostgreSQL pilot archive includes `LICENSES/inventory.json`. Its component entries identify the PostgreSQL or runtime package version, the PostgreSQL payload directories or exact copied runtime library paths, the included license text, and a source URL. The bundled glibc and static launcher entries also identify exact source-package versions and source archives; the glibc entry lists referenced licence texts. The archive carries standard licence texts referenced by package copyright files. The archive verifier checks that mapped files and licence texts exist in the extracted archive and that every copied runtime library and launcher binary has exactly one package mapping. This checks archive provenance and mapping completeness; it does not determine whether a licence permits redistribution. The inventory writer may attach explicit redistribution reviews keyed by exact component, package and version; when a review file is supplied it must cover every packaged component with a resolved decision. Without that file the pilot inventory remains provenance-only and cannot pass publication preflight. A fixture archive generated with complete review declarations passes the preflight's structural check; this does not establish that any actual component's terms have been reviewed.
The PostGIS Linux pilot also includes `LICENSES/postgis/inventory.json`. It maps the selected SQL modules, extension scripts, each copied runtime library, and the PROJ and GDAL data directories to the PostGIS or Ubuntu package version, included licence text, and exact-version source link. Runtime libraries already present in the PostgreSQL archive must match byte-for-byte after runtime-path patching and are covered by the core inventory. The PostGIS entry records the downloaded source archive's SHA-256. The archive includes the standard licence texts referenced by package copyright files. Its verifier checks these mappings and referenced texts against the extracted payload; a source URL is evidence of where to obtain source, not a legal conclusion about redistribution. Records must distinguish pilot smoke checks from publication checks. A publication record must give one `passed`, `failed`, or `skipped` result for every case in its profile, with no extra cases; its aggregate outcome must follow those results. A passing publication record must name a full test commit, unique case identifiers, the verification image, and the runtime dependency-check profile and result. An extension publication record must also name the exact PostgreSQL archive used for assembly. Candidate generation and coverage compare its checksum with the core download claimed for each tested PostgreSQL endpoint; a version match alone cannot establish that the advertised archives work together. When an extension declares another extension project as a prerequisite, its publication receipt and record must also bind that project's exact archive filename, version and SHA-256. Candidate generation, coverage and preflight must match each prerequisite claim to the corresponding downloadable archive for the tested PostgreSQL endpoint. Pilot records remain useful for development but must not satisfy publication coverage. The profile registry binds each record to a named case set and the current content of its test sources. Linux publication profiles hash marked case-execution and outcome-recording sections of the workflow, plus shared job setup, receipt creation and record emission. Missing or duplicate section markers invalidate the profile. Artifact-upload edits outside those sections do not stale matching archive evidence; changes to test execution, outcome mapping or its environment do. macOS and Windows builder scripts are excluded from test-profile hashes because archive checksums and build revisions identify the bytes separately; an unchanged test suite remains applicable to previously tested archive bytes after a build-only edit. UTF-8 text line endings are normalized to LF before hashing so identical Windows and Unix checkouts have the same profile revision; binary sources remain byte-exact. Earlier all-CRLF profile digests remain applicable only while their normalized source content matches. A changed suite makes old records stale without discarding them.
