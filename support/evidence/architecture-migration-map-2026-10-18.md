# Architecture migration map, 18 October 2026

This map records the active publication and investigation paths before the remaining pgTAP macOS arm64 predecessors are removed. It supports the Architecture migration inventory item in `GOAL_BACKLOG.md`. Workflow counts come from `python3 tools/architecture_inventory.py` on 18 October 2026: 86 workflows total, including 43 publication, 39 investigation and 4 infrastructure workflows. The inventory's category is a workflow classification, not proof that every listed profile is currently selected in `support.json`.

“Selected path” below means a workflow now accepts/selects the PostgreSQL target(s) for the named project/platform family, as indicated by its workflow name and profiles. “Pending” means the family still needs migration comparison or confirmation against the reviewed architecture policy. Workflow selection does not establish release eligibility. Recipe, verifier, emitter and importer filenames are observed current paths. Any proposed destination is explicitly marked.

## Planner and candidate retrieval tools

The current planning path is split across `tools/plan_work.py`, `tools/extension_archive_plan.py` and `tools/extension_work_queue.py`. `plan_work.py` compares declared support, available archives and verification records to report missing core/extension builds and checks; `extension_archive_plan.py` groups declared extension targets as explicitly unverified archive candidates; `extension_work_queue.py` expands targets into dependency-ordered build and verification tasks and can consume a candidate manifest. `tools/candidate_archive_cache.py` validates local candidate files, checksums, target metadata and source run/artifact claims. These tools provide inspectable planning, prerequisite relationships and checked local candidate reuse. They do not yet establish freshness against intended source/dependency/build configuration/recipe inputs, retrieve candidate bytes from Actions, or dispatch bounded tasks to CI. `tools/reuse_linux_core_artifact.py` is a narrow best-effort exception: it locates a same-commit Linux pilot workflow artifact for x86-64 or arm64 and checks the PostgreSQL record/archive checksum before reuse; callers may fall back to building core. It is not a general retrieval path and remains tied to named pilot workflows. Proposed migration destination: planner-driven bounded workflow dispatch plus durable checked candidate retrieval or rebuild, with applicability rules from `policies/architecture.md`; this destination is not yet implemented.
