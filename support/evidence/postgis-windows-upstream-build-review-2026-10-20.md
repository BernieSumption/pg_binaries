# PostGIS 3.6.4 Windows build route

The selected Windows PostgreSQL archives use MSVC. No retained trial has loaded PostGIS 3.6.4 into one of those exact archives. The [selected-core ABI trial](../../experiments/postgis-windows-abi-trial/README.md) instead asks PostGIS's GCC build to consume the MSVC core's `pg_config` and PGXS files; it reached configuration and shared-library compilation but stopped in the toolchain adapter before producing a loadable module.

The [PostGIS 3.6.4 source root](https://github.com/postgis/postgis/tree/3.6.4) provides Autoconf and GNU Make entry points. Its [configure input](https://github.com/postgis/postgis/blob/3.6.4/configure.ac) initializes Libtool, selects a C compiler through Autoconf, and uses GNU-style link flags. The [tagged MSYS2 workflow](https://github.com/postgis/postgis/blob/3.6.4/.github/workflows/msys.yml) is disabled with `if: false`; its configured job uses `clang64` and `--without-protobuf`. These files do not establish a maintained direct MSVC build route for the complete selected feature set. They do not prove that the PostGIS C code cannot compile with MSVC.

PostGIS's [Winnie build script](https://github.com/postgis/postgis/blob/3.6.4/ci/winnie/build_postgis.sh) uses MinGW and the matching PostgreSQL build prefix. Its [regression script](https://github.com/postgis/postgis/blob/3.6.4/ci/winnie/regress_postgis.sh) also has an extension-test path that copies built PostGIS DLLs and SQL files into a second prefix named `PGPATHEDB`, then runs `make check` with `--extension`. The [shared configuration](https://github.com/postgis/postgis/blob/3.6.4/ci/winnie/winnie_common.sh) defines distinct MinGW and EDB prefixes. Inference: building with a same-version MinGW PostgreSQL toolchain, then verifying the resulting PostGIS DLL against a separate Windows PostgreSQL installation, is an upstream-used route. The scripts do not identify the second installation's exact compiler or prove compatibility with this project's selected core bytes.

Keep the required raster, SFCGAL, topology and TIGER capabilities as later gates; a reduced-feature module-load probe would establish the cross-toolchain boundary only. If it fails, retain the exact loader or SQL error before considering a core replacement or a direct MSVC build recipe. No source patch or production policy change follows from this review alone.
