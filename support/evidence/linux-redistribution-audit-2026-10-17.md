# Linux PostgreSQL redistribution evidence audit

The PostgreSQL 18.6 Linux x86-64 archive from [publication run 39003088887](https://github.com/BernieSumption/pg_binaries/actions/runs/39003088887) has SHA-256 `518f724176dd953fc2c373fef7d9a72939d459d80b16993db6c984dd2fbdc66b`. This is a historical pilot archive, not a proposed release asset. Its `LICENSES/inventory.json` maps PostgreSQL and 13 bundled runtime packages to payload paths and included copyright or licence files. None of the 14 components has a `redistribution_review` declaration, so [the release preflight](../../policies/releases.md) must reject this archive.

The runtime package identities recorded in the archive are `libc6` 2.35-0ubuntu3.15, `libgcc-s1` 12.3.0-1ubuntu1~22.04.3, `libicu70` 70.1-2, `liblz4-1` 1.9.3-2build2, `liblzma5` 5.2.5-2ubuntu1.1, `libssl3` 3.0.2-0ubuntu1.30, `libstdc++6` 12.3.0-1ubuntu1~22.04.3, `libuuid1` 2.37.2-4ubuntu3.6, `libxml2` 2.9.13+dfsg-1ubuntu0.14, `libxslt1.1` 1.1.34-4ubuntu0.22.04.5, `libzstd1` 1.4.8+dfsg-3build1, `musl` 1.2.2-4, and `zlib1g` 1:1.2.11.dfsg-2ubuntu9.2. Only `libc6` and `musl` record source-package names, source versions and exact source-archive URLs. The other package-page URLs do not identify the source material required for their exact binary versions. The inventory writer has since been changed to record source-package names and versions for every bundled package; this historical archive remains unchanged.

The later x86-64 and arm64 archives from [run 39021867664](https://github.com/BernieSumption/pg_binaries/actions/runs/39021867664) have SHA-256 values `7d86fa7f76df22f0140da789df98d0da8738e8b98152b8cbcbecd7720d61b214` and `7a96cce0649d0db97f7ea55515cd1363e659282cbd0bf0b3def56f9c978ff1ec`, respectively. Direct inspection of each archive's `LICENSES/inventory.json` found a source-package name and version for all 13 bundled runtime packages; `zlib1g` maps to source package `zlib` version `1:1.2.11.dfsg-2ubuntu9.2`. The archives still have no resolved redistribution reviews. Source identity alone does not establish the applicable file-level notices, whether Ubuntu modifications introduce further obligations, or that any required source is available to download.

The included `PostgreSQL.txt` notice supports a candidate `source_obligation: none` decision for PostgreSQL: the [PostgreSQL licence](https://www.postgresql.org/about/licence/) requires its copyright, permission and disclaimer text in copies, and the archive contains that text. For `zlib1g` `1:1.2.11.dfsg-2ubuntu9.2`, the [exact Ubuntu package copyright file](https://changelogs.ubuntu.com/changelogs/pool/main/z/zlib/zlib_1.2.11.dfsg-2ubuntu9.2/copyright) covers the source and `debian/*` under the Zlib licence. Its origin and altered-source conditions do not require source delivery with redistributed shared objects; its notice-retention condition applies to source distributions. The archive includes that copyright file, and the newer archive records the exact source-package identity. This supports a version-keyed `source_obligation: none` review for the shipped zlib shared objects. No review declaration has yet been attached to final archive bytes, and neither conclusion clears the other bundled components.

For `liblz4-1` `1.9.3-2build2`, the [exact Ubuntu copyright file](https://changelogs.ubuntu.com/changelogs/pool/main/l/lz4/lz4_1.9.3-2build2/copyright) assigns `lib/*` to BSD-2-Clause and the separate utility programs to GPL-2-or-later. The archive ships the shared library, not the utility programs, and includes that copyright file. Its binary notice requirement is therefore met by the included text, and it imposes no source-delivery obligation for this library. This supports a version-keyed `source_obligation: none` review for the shipped LZ4 library; the declaration is not yet attached to final archive bytes.

For `libuuid1` `2.37.2-4ubuntu3.6`, the [Ubuntu source manifest](https://archive.ubuntu.com/ubuntu/pool/main/u/util-linux/util-linux_2.37.2-4ubuntu3.6.dsc) identifies the upstream archive (SHA-256 `6a0764c1aae7fb607ef8a6dd2c0f6c47d5e5fd27aa08820abaad9ec14e28e9d9`) and packaging delta (SHA-256 `d556ef8fb39638a6fee023dc02d1ed4c9a15d6065f844fa885ddb5b9e755ae31`); both downloaded files matched. The exact upstream `libuuid/src/Makemodule.am` lists `lib/randutils.c`, `lib/md5.c` and `lib/sha1.c` alongside `libuuid/src/*` as library inputs. Its `randutils.c` header declares BSD-3-Clause, while the exact Ubuntu `debian/copyright` assigns that file LGPL and `libuuid/*` BSD-3-Clause. The MD5 and SHA-1 source headers declare public-domain status. None of the 29 listed Ubuntu patches changes those four source paths. The archive includes the package copyright file. Treat the conflicting declaration conservatively: retain both applicable notices and make the exact Ubuntu source package, including its packaging delta, available with the binary. Confirm that the archive carries the full notice and LGPL terms before recording a resolved review; the `libuuid/*` stanza alone does not justify `source_obligation: none`.

For bundled `libgcc-s1` and `libstdc++6` `12.3.0-1ubuntu1~22.04.3`, Ubuntu identifies `gcc-12` as their source package. The [FSF's GCC Runtime Library Exception FAQ](https://www.gnu.org/licenses/gcc-exception-3.1-faq.en.html) says the exception can permit eligible programs linked to the runtime, but independently redistributing libstdc++ object code still requires following GPLv3's source-conveyance terms. The same source-delivery question applies to the separately bundled libgcc runtime; the exception is not a substitute for its own notices or corresponding source. Candidate clearance therefore needs the exact Ubuntu GCC source and packaging delta, the applicable GPL and exception texts in the archive, and an accessible source-delivery path alongside the binary. The exact Ubuntu copyright and final shared-object provenance remain to be checked.
