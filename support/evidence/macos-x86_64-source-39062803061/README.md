# Intel macOS source-built archive pilot

[Run 39062803061](https://github.com/BernieSumption/pg_binaries/actions/runs/39062803061) at revision `75f27f6a0cad0c6ad515d4db55dba0f6cd85304a` built PostgreSQL 18.6, pgvector 0.8.7 and their macOS dependencies from pinned upstream sources for x86-64. A separate `macos-15-intel` runner passed relocation, archive behaviour, built-in and pgvector SQL, symbol verification and [static analysis](static-analysis.json). The report inspected 133 Mach-O files, found no dependency or minimum-target violations, and recorded macOS 11.0 as every inspected file's deployment target.

The PostgreSQL archive SHA-256 is `d093795b34b19156b31389ec1fa639d6d9266c3e95fbd756dc2dc848ba28c3bc`; the pgvector archive SHA-256 is `eac671ba5f8c991ff09ed80463a78d2ea33ffec8012bbffa4b4632f17ee68a09`. Both downloaded archive hashes match the static report and the [PostgreSQL](../../verification/postgresql-18.6-macos-x86_64-39062803061.json) and [pgvector](../../verification/vector-18.6-macos-x86_64-39062803061.json) passing records. These records describe their producing revision; subsequent verification-profile edits require a new run for current evidence.

The independent `check_macos_license_inventory.py` check on these downloaded archives mapped 136 native PostgreSQL payload paths across seven declared components and the pgvector module to nonempty licence texts. The exact [PostgreSQL licence inventory](license-inventory.json) is retained. This run predates the check's integration into routine verification. Component redistribution reviews remain pending in these archive bytes, so this pilot is not publication clearance.
