# PostGIS 3.6.4 cross-toolchain Windows load probe

On 2026-10-20, [run 39509897265](https://github.com/BernieSumption/pg_binaries/actions/runs/39509897265) passed on the standard Windows 2022 x86-64 runner. It built unmodified PostgreSQL 18.6 and PostGIS 3.6.4 in MSYS2 MINGW64, then copied the resulting `postgis-3.dll` and PostGIS SQL/control files into the checked, selected MSVC-built PostgreSQL 18.6 archive. That selected server started, executed `CREATE EXTENSION postgis`, created a table with a `geometry(Point, 4326)` column, and returned `POINT(1 2)` after inserting and reading a geometry. `postgis_full_version()` reported PostGIS 3.6.4 and PostgreSQL ABI 180.

This resolves the narrow module-load question for that exact version pair and runner. The trial exposed `/mingw64/bin` and the MinGW installation on `PATH`; it did not package or verify the dependency closure. It excluded raster, topology, TIGER, SFCGAL and protobuf, and produced no relocatable extension archive or final-byte verification record. The publication recipe still needs those declared features, bundled runtime dependencies, redistribution review, and clean-runner verification for each selected target.
